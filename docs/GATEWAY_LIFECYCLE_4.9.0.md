# Gateway lifecycle 4.9.0 — 2026-10-02

The gateway converts authorized web chat into API responses while Agent CLI retains task, tool and wallet authority. Typed context is validated against the generated Protocol schema before a browser session is created. Regenerate `src/contracts/context-schema.ts` with Protocol's `scripts/export_context_schema.py`; the ecosystem gate checks exact source parity.

One serial session lease covers initial generation and semantic/serialization repairs. A 240-second default deadline spans queueing and all attempts. Agent metadata can reduce deadline, cumulative prompt allowance and the maximum of three upstream attempts. Built-in UI/network transports charge immediately before submission; third-party executors must invoke `options.lifecycle.beforeSubmit(renderedPrompt)` and `received(output)` to get pre-dispatch prompt enforcement. Legacy plugin fallback charges on completion and cannot verify the exact prompt before dispatch.

Idempotency keys are scoped to the manager/session and original body. Preparation happens after entering the actual session lease. Pending entries do not expire or get evicted; pre-submit failures release the key. Submitted failures are retained as uncertain for the process lifetime. Capacity (512 entries) rejects new work when every entry is pending or uncertain. Successful entries have a five-minute retention window and may be evicted. Replays charge zero usage. This provides no durable exactly-once guarantee across restart or after successful-entry eviction; reconcile provider state before generating a new key for an uncertain request.

Context acknowledgement is committed after provider response. Session instance/generation changes, reset, eviction and errors invalidate it. Fingerprints are per segment and tool schema; changing one segment sends the changed data and explicit removals without repeating unchanged schemas. Network transport bootstraps each stateless request. Repair prompts retain the original task, typed context, tool definitions and bounded invalid candidate, all as untrusted evidence under the English gateway persona.

Streaming opens immediately, uses SSE heartbeats on OpenAI/Responses/Anthropic, limits pending output to 4 MiB and bounds drain waits to ten seconds. API completion text must extend the exact emitted prefix. Rewritten live text produces an explicit error instead of a successful terminal marker; buffered text uses only the canonical result. Ollama final chunks do not duplicate previously emitted text. Required JSON output is validated or returns an error. API model names for UI transport are aliases: the observed web model is not verified.

Usage includes initial generation, hidden repairs and upstream attempts. UI accounting is an estimate, not a billing tokenizer; this release conservatively estimates network exchange payloads as well. Estimates and replay state are explicit. Failed requests include usage, identity and an uncertain outcome where available. Cancelling transport does not prove the upstream provider stopped computing.

Resource admission includes browser pages and bounded Linux process-tree PSS (512 processes, 2,048 pending PIDs, 32 threads/process, a 50 ms sampling budget, five-second cache), including a shared browser PID supplied by the control plane. Shared mappings are not double-counted. Measurement exposes its mode and partial coverage. Other systems use Node RSS fallback and require external process/container limits for browser memory. Protected busy/tool-wait sessions are retained and new admission fails under pressure. Provider circuit state is shared across sessions of the same manager/provider/transport.

Validation: TypeScript check/build and complete Node suite; focused regressions for pending/uncertain idempotency, queue cancellation, cumulative grants/deadlines, buffered/live rewrites and protocol writer mismatch. Real web-provider DOM behavior and Windows/macOS memory sampling are not validated by these local tests.
